# CLAUDE.md

Это руководство для Claude Code при работе с этим репозиторием.

## Проект

`fastcart-server` — собственный бэкенд для интернет-магазина fastcart
(отдельный репозиторий, отдельный деплой от фронтенда). Он **не заменяет**
основной бэкенд `fastcard-1-o23z` (auth, каталог товаров, категории и т.д.),
а дополняет его двумя вещами, которых там нет: баннеры hero-слайдера на
главной и заказы.

Фронтенд (репозиторий `fastcart`, соседняя папка) ходит сюда через второй
axios-инстанс `src/api/customApi.ts` (`VITE_CUSTOM_API_URL`), отдельно от
основного `src/api/axios.ts`.

## Стек

- Node.js + TypeScript
- Express 5
- PostgreSQL + [Drizzle ORM](https://orm.drizzle.team/) (не Prisma — его
  движок для миграций блокируется Windows Application Control Policy на
  машине разработчика; Drizzle работает через чистый JS-драйвер `pg`, без
  нативных бинарников)
- `swagger-ui-express` + `swagger-jsdoc` — документация на `/api/docs`,
  описывается JSDoc-комментариями `@openapi` прямо над роутами

## Деплой

- Прод: **Render** (Web Service), URL — `https://fastcart-server.onrender.com`.
  Бесплатный тариф — засыпает после ~15 мин бездействия, первый запрос после
  сна отвечает с задержкой 10–30 сек (это нормально, не баг).
- **Auto-Deploy на Render отключён** (важно!). После `git push` в `main`
  нужно вручную зайти в Render Dashboard → сервис → **Manual Deploy → Deploy
  latest commit**, иначе прод продолжит работать на старой версии кода.
- База данных — PostgreSQL от Prisma (`db.prisma.io`), заведена через
  `npx create-db`, потом "заклеймлена" в постоянный аккаунт. Никак не связана
  с самим Prisma ORM — используется просто как хостинг Postgres, доступ через
  `DATABASE_URL` и Drizzle.

## Как устроена авторизация

Токен (JWT) выдаёт **основной** бэкенд при логине/регистрации. Этот сервис
не может проверить его подпись — у него нет секретного ключа основного
бэкенда. Поэтому `src/middleware/auth.ts` только **декодирует** токен
(`jwt.decode`, не `jwt.verify`) и достаёт из него `id` и `role`.

Это осознанный компромисс для учебного проекта: теоретически можно собрать
токен с любым `id`/`role` без пароля. Для настоящего продакшена нужно либо
получить общий секретный ключ от того, кто держит основной бэкенд, либо
перевести всю авторизацию на один бэкенд.

Два middleware:

- `requireAuth` — любой валидный неистёкший токен (используется для роутов
  заказов обычных пользователей).
- `requireRole(...roles)` — то же самое + проверка ролей (используется для
  записи в баннеры и для всех admin-only роутов заказов).

## Архитектура

- `src/index.ts` — точка входа: express-app, CORS (`FRONTEND_ORIGIN`),
  `/api/docs` (Swagger UI), монтирует роутеры `/api/banners` и `/api/orders`.
- `src/db/schema.ts` — Drizzle-схема, три таблицы: `banners`, `orders`,
  `orderItems` (см. ниже).
- `src/db/index.ts` — подключение к Postgres через `pg.Pool` + `drizzle()`.
- `src/middleware/auth.ts` — `requireAuth`/`requireRole`, декодирование JWT.
- `src/routes/banners.ts` — CRUD баннеров.
- `src/routes/orders.ts` — заказы (создание, чтение, admin-эндпоинты).
- `src/swagger.ts` — конфиг `swagger-jsdoc`, собирает спеку из JSDoc в
  `src/routes/*.ts`.

### Модель данных

- **banners** — `eyebrow`, `title`, `imageUrl`, `imageAlt`, `linkUrl`,
  `sortOrder`, `isActive`. `imageUrl` — просто строка-ссылка в БД; сам файл
  заливается отдельным шагом через `POST /api/banners/upload` (multer,
  `src/middleware/upload.ts`), сохраняется на диск в `uploads/` и отдаётся
  статикой (`app.use("/uploads", express.static(...))` в `src/index.ts`).
  **Важно**: на бесплатном Render диск эфемерный — файлы пропадают при
  каждом новом деплое или когда инстанс "просыпается" после сна. Для
  учебного проекта это осознанный компромисс; для настоящего прода нужно
  внешнее хранилище (S3, Cloudinary и т.п.).
- **orders** — данные доставки (имя, адрес, телефон, email), `paymentMethod`
  (`"bank" | "cod"`), `subtotal`, `status` (см. ниже), `userId` — **не**
  внешний ключ на таблицу пользователей (пользователи живут в другой базе на
  основном бэкенде, доступа к ней нет).
- **orderItems** — товары внутри заказа хранятся **снимком** на момент
  покупки (`productId`, `productName`, `price`, `quantity`), а не ссылкой на
  живой каталог — каталог тоже живёт на другом бэкенде и может измениться
  или удалиться позже. `onDelete: "cascade"` — удаление заказа удаляет и его
  позиции автоматически.
- Статусы заказа (`orders.status`), единый список в
  `ORDER_STATUSES`/`ORDER_STATUS_LABELS` (продублирован и во фронтенде в
  `src/lib/orderStatus.ts` — при добавлении нового статуса менять в обоих
  местах): `pending`, `processing`, `shipped`, `delivered`, `cancelled`.

## API

Полная актуальная спека — `/api/docs` (Swagger UI). Коротко:

### Баннеры (`/api/banners`)

- `GET /` — публичный список **активных** баннеров, по `sortOrder`
- `GET /all` — список **всех** баннеров, включая неактивные (только
  `Admin`/`SuperAdmin`) — использует админка, т.к. иначе выключенный баннер
  пропал бы из списка без возможности включить его обратно
- `POST /upload` — загрузить файл картинки (`multipart/form-data`, поле
  `image`, только `Admin`/`SuperAdmin`), возвращает `{ data: { imageUrl } }`
  — этот URL потом передаётся в `imageUrl` при создании/обновлении баннера
- `POST /` — создать (только `Admin`/`SuperAdmin`)
- `PUT /:id` — обновить (только `Admin`/`SuperAdmin`)
- `DELETE /:id` — удалить (только `Admin`/`SuperAdmin`)

### Заказы (`/api/orders`)

Все роуты требуют `Authorization: Bearer <token>`.

- `POST /` — создать заказ (данные доставки + список товаров-снимков)
- `GET /` — список заказов **текущего** пользователя, с позициями
- `GET /all` — **все** заказы всех пользователей, с позициями (только
  `Admin`/`SuperAdmin`) — используется дашбордом и таблицей заказов админки
- `PATCH /:id/status` — сменить статус заказа (только `Admin`/`SuperAdmin`),
  тело `{ status: string }`, валидируется против `ORDER_STATUSES`
- `DELETE /:id` — удалить заказ (только `Admin`/`SuperAdmin`); позиции
  удаляются каскадно
- `GET /:id` — один заказ **текущего** пользователя с позициями

## Команды

```bash
npm run dev          # tsx watch — дев-сервер на http://localhost:4000
npm run build        # tsc — компиляция в dist/
npm run start        # запуск собранной версии (dist/index.js)
npm run db:generate  # сгенерировать SQL-миграцию из схемы
npm run db:push      # применить текущую схему к базе напрямую (для разработки)
npm run db:studio    # Drizzle Studio — веб-интерфейс для просмотра таблиц
```

## Переменные окружения

| Переменная | Описание |
| --- | --- |
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `PORT` | Порт сервера (Render подставляет свой автоматически) |
| `FRONTEND_ORIGIN` | Домен(ы) фронта, разрешённые для CORS, через запятую |

- Я начинающий junior frontend разработчик, в бэкенде не силён — объясняй
  сложные моменты (SQL, транзакции, JWT и т.п.).
- Не используй `any`.
- Предпочитай простые решения.

  решили переходом на Drizzle, а не обходом политики).
